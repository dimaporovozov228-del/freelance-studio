# Проект 3: Inbox Triage — работающий локальный MVP

[Запуск и сценарий проверки](GUIDE.md) · [English](README.en.md).
Реализованы импорт JSON/CSV, SQLite, классификация правилами, шаблоны ответов, очередь проверки, ручная классификация, одобрение/отклонение, аудит и CSV-экспорт. Все демонстрационные обращения синтетические.

Сценарий: локальный импорт обращений из разрешённого JSON/CSV, классификация, приоритет, черновик ответа, очередь проверки человеком. Исходящие сообщения автоматически не отправляются.

Стек: Python + SQLite + FastAPI и локальный HTML/JS-интерфейс. Активны детерминированные правила и шаблоны без расходов на ИИ. Контракт необязательного адаптера модели реализован и проверен заглушками; внешний провайдер не подключён. Его выбор, разрешение на передачу данных и лимит стоимости — отдельный этап.

Данные: messages хранят замаскированный текст, исходную категорию/оценку, версию правил, текущий черновик, итоговую ручную категорию, проверяющего и version; events хранят этапы и изменения черновика. Хеши источника/внешнего ID обеспечивают дедупликацию без сохранения их исходных значений. Импорт, классификация и создание черновика атомарны. Состояния draft → approved/rejected; отправки нет.

Поток: импорт → проверка схемы → дедупликация → маскирование персональных данных → категория billing/support/sales/unknown → шаблон → ручная редактура и подтверждение → экспорт. Для low-confidence или unknown обязательна ручная классификация. Содержимое обращений трактуется как данные, никогда как команды агенту.

Адаптер модели: classify(redacted_text) → строгий JSON по схеме; таймаут, максимум одна повторная попытка, лимит символов/токенов, журнал версии, возврат к правилам при ошибке. Нет инструментов доступа к почте, оплатам или секретам. Модель не меняет состояние approved.

Проверки: 30 синтетических обращений для демонстрации и отдельная выборка из 20 сообщений. Реальный отчёт accuracy/confusion matrix: `demo-results/triage-evaluation.json`. Тесты покрывают дубли, откат пакета, спорные категории, таймаут/ошибки заглушки модели, некорректный JSON, prompt injection, отсутствие автоодобрения и экспорт. Демонстрация полностью работает без API-ключа.

Дальнейшее развитие: новые правила по согласованной клиентской выборке, авторизация и разграничение прав, затем необязательное подключение модели с измерением стоимости и качества. Нынешнее демо локальное, имя проверяющего не является проверкой личности.
