# Inbox Triage: загрузка → черновик → проверка

Локальный демонстрационный проект автоматизации обращений. Все примеры синтетические. Работающая версия использует правила и шаблоны; внешняя ИИ-модель не подключена. Сообщения никому не отправляются, экспорт содержит только одобренные черновики.

## Запуск

Из корня `freelance-studio`, Python 3.11+:

```powershell
py -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[api,test]"
.venv/Scripts/python.exe -m studio.triage.cli serve
```

Если окружение уже существует, пропустите первую команду. Откройте http://127.0.0.1:8767. Linux/macOS: `python3`, затем `.venv/bin/python`. Команда `inbox-triage` также доступна после установки. Сервер слушает только 127.0.0.1; остановка Ctrl+C. Параметры: `--port 8767`, `--db data/inbox.sqlite3`. Используйте отдельную БД, не базу Order Desk. При первом запуске схема создаётся автоматически, версия хранится в PRAGMA user_version; неизвестная версия/чужая БД отклоняется. Будущие изменения схемы потребуют новой миграции.

## Проверка за пять минут

1. Нажмите «Загрузить 30 примеров». Повторное нажатие пропустит те же обращения.
2. Выберите обращение об оплате, поддержке или покупке. Прочитайте текст, категорию и черновик. Email/телефоны в поддерживаемых форматах замаскированы.
3. Отредактируйте черновик, укажите имя проверяющего и нажмите «Сохранить правки» либо «Одобрить черновик». Одобрение требует подтверждения. Откройте историю — там будут этапы и сохранённые изменения.
4. Выберите «Нужно уточнить». Перед одобрением выберите оплату/поддержку/продажи и отметьте «Я проверил выбранную категорию». Проверьте также сам текст ответа: смена категории не заменяет черновик автоматически.
5. Нажмите «Скачать одобренные CSV». В файл попадут только одобренные записи. Отклонённые и ожидающие проверки не экспортируются. Если ничего не одобрено, CSV содержит только заголовки.

Одобренное/отклонённое обращение окончательно для этого демо. Повторная обработка и история пересмотра итоговых решений пока не реализованы. При конфликте версии обновите очередь и заново выберите сообщение; несохранённый текст лучше скопировать перед обновлением.

## Свои файлы и командная строка

Только разрешённые собственные обезличенные JSON/UTF-8 CSV. Требуются `source`, `external_id`, `body`, `received_at`; лишние поля отклоняются. received_at — ISO 8601 с часовым поясом. JSON: массив объектов; CSV: заголовки строго в этом порядке. Пример: `examples/triage-import.csv`. Полный JSON демо: `studio/triage/sample_messages.json` (включён в пакет).

В интерфейсе раскройте импорт, выберите файл и укажите основание использования данных. Эта запись фиксирует ваше утверждение о разрешении, но не доказывает его юридически.

```powershell
.venv/Scripts/python.exe -m studio.triage.cli seed
.venv/Scripts/python.exe -m studio.triage.cli import --input examples/triage-import.csv --permission-note "Собственные синтетические данные"
.venv/Scripts/python.exe -m studio.triage.cli export --output reports/approved-drafts.csv
.venv/Scripts/python.exe -m studio.triage.cli evaluate --input examples/triage-evaluation.json --output reports/triage-evaluation.json
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Лимиты: 512 КиБ UTF-8 текста на импорт, 1..1000 записей, до 10000 символов обращения, до 5000 символов ответа. Списки API: limit 1..100, offset >=0; интерфейс показывает по 20 записей. Текст и время записи с тем же source/external_id должны совпадать; иначе весь пакет откатывается. Ключ учитывает исходные идентификаторы, хранимые в виде SHA-256; отображаются замаскированные значения.

## Правила и измеренное качество

Категории billing/support/sales определяются словарями русского и английского языка. Несколько категорий, отсутствие ключевых слов или обнаруженный маркер вмешательства в инструкции дают unknown. Срочность — отдельный поиск urgent/asap/срочно; SLA не рассчитывается.

Оценки 0.9/0.0 — внутренние значения правил, не откалиброванные вероятности. Для unknown и оценки ниже 0.8 нужна ручная категория. Любой импорт создаёт draft, ни правила, ни модель не могут одобрить запись.

На отдельной небольшой авторской синтетической выборке: **16 из 20 верных категорий (80%)**, матрица и все предсказания в `demo-results/triage-evaluation.json`. Четыре пропущенные категории отправлены в unknown из-за отсутствующих ключевых слов. Это не независимая оценка и не обещание качества на данных клиентов. Для новой задачи нужно согласовать категории, разметить отдельную проверочную выборку и повторить измерение.

## Необязательная модель

`ClassifierAdapter.classify(body, timeout) → JSON string` — контракт в `studio/triage/rules.py`, без конкретного провайдера и API-ключа. Подключение доступно из Python, но не через веб-форму/CLI. На входе маскирование и максимум 4000 символов. На попытку 3 секунды, максимум две попытки, строгие поля category/confidence/priority/rationale, запрет лишних полей (например approved). Неправильный JSON, ошибка или таймаут → правила. Двусмысленные/подозрительные сообщения остаются unknown без вызова адаптера.

Одновременно разрешено до двух фоновых вызовов; зависший вызов не блокирует обработку после таймаута, но поток нельзя принудительно остановить, и он удерживает слот до завершения. Будущий провайдер обязан также применять сетевой timeout; лимиты символов не являются лимитом токенов или расходов. Реальная интеграция потребует отдельного разрешения на передачу данных, лимита стоимости, версии модели и проверки качества. В этой версии расходов на модель нет.

## Ограничения

Приложение локальное, без проверки личности и разграничения пользователей. Имя проверяющего — запись аудита, а не авторизация. Страница выдаёт временный токен для изменения данных; после перезапуска обновите страницу. Автопроцесс классификации не одобряет сообщения, но любой пользователь с локальным доступом к форме может вызвать ручной endpoint. Для бизнеса нужна настоящая авторизация.

В SQLite сохраняются замаскированный текст, хеши идентификаторов/исходного тела, решения и история редактирования. Маскирование не гарантирует полное удаление персональных данных: имена, адреса, секреты, необычные форматы телефонов могут остаться. Длинные номера могут маскироваться как телефоны. Используйте только заранее обезличенные данные. БД исключена из Git; аудит не защищён от прямого изменения файла. Резервную копию делайте при остановленном сервере.

Входные сообщения никогда не исполняются как команды; интерфейс выводит их через textContent, а CSV экранирует префиксы формул. Детектор prompt injection — примеры правил, не гарантия обнаружения всех атак. Нет чтения почтового ящика, CRM-интеграции, автопоиска сообщений и отправки ответов. Тесты моделируют действия проверяющего; они не заменяют проверку реальным пользователем. Публичное размещение не предусмотрено.
