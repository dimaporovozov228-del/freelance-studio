# Order Desk: запуск и демонстрация

Это локальный демонстрационный проект портфолио, а не коммерческий клиентский кейс. Все примеры синтетические. FastAPI + SQLAlchemy Core + Alembic + SQLite; платные сервисы не нужны.

## Установка

Из корня `freelance-studio`, Python 3.11+:

```powershell
py -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[api,test]"
.venv/Scripts/python.exe -m studio.orderdesk.cli migrate
.venv/Scripts/python.exe -m studio.orderdesk.cli seed
.venv/Scripts/python.exe -m studio.orderdesk.cli serve
```

Если окружение создано, первую команду пропустите. На Linux/macOS используйте `python3` и `.venv/bin/python`. После установки доступна также команда `order-desk`.

Откройте http://127.0.0.1:8766/docs. Выберите endpoint → Try it out → Execute. Схема: `/openapi.json`, проверка здоровья: `/health`. Остановка: Ctrl+C.
По умолчанию БД: `data/orderdesk.sqlite3`, путь относительно текущего рабочего каталога. Параметры CLI: `--db другой/файл.sqlite3`, `--port 8766`. Миграции применяются и автоматически при старте сервера. Seed добавляет одного клиента и два товара только при пустых таблицах customers/products; иначе пропускается. БД не публикуется в Git.

## Проверка через настоящий HTTP

При запущенном сервере из второго терминала в корне проекта:

```powershell
.venv/Scripts/python.exe -m studio.orderdesk.demo
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Демо создаёт нового синтетического клиента, товар и заказ на 20100 копеек (=201.00 RUB), подтверждает и завершает заказ; проверяет повтор запроса, конфликт ключа, устаревшую версию и три события аудита. Каждый запуск добавляет отдельные демоданные. Протокол: `reports/orderdesk-demo.json`; записанный результат поставки: [demo-results/orderdesk-demo.json](../../demo-results/orderdesk-demo.json).

## Ручной сценарий в /docs

После seed в пустую БД клиент и товар имеют ID 1. Для POST `/orders` задайте заголовок `Idempotency-Key: example-order-1` и тело:

```json
{"customer_id":1,"currency":"RUB","items":[{"product_id":1,"quantity":2,"price_minor":10050}]}
```

Запомните ID из ответа. Для PATCH `/orders/{id}/status` передайте `{"status":"confirmed","version":1}`, затем `{"status":"completed","version":2}`. GET `/orders/{id}/events` покажет историю. GET `/orders/{id}` вернёт текущее состояние.

## Правила и границы

- GET `/customers`, `/products`, `/orders`: массив, `limit` 1..100 (по умолчанию 20), `offset` >=0, порядок по ID; общего числа записей нет.
- Цена — целое число минимальных единиц, 0..1000000000; количество — целое 1..1000000. Дроби, строки вместо чисел и булевы значения отклоняются. До 100 разных товаров в заказе.
- Валюта явно задаётся на заказ: RUB, USD или EUR, без конвертации. SKU — латинские буквы, цифры, дефис/подчёркивание, до 64 символов, нормализуется в верхний регистр. Проверка email — базовая синтаксическая, без проверки доставки.
- Статусы: draft → confirmed → completed; из draft/confirmed доступен cancelled. Completed/cancelled окончательны. Успешный переход увеличивает version; устаревшая версия/неверный переход → 409 без записи события.
- Создание заказа, позиций, аудита и ключа — одна транзакция. Неизвестный клиент/товар → 404 с полным откатом. Ошибка схемы → 422; повтор SKU → 409. Ограничения чисел и внешние ключи действуют в самой SQLite.
- Повтор Idempotency-Key с тем же нормализованным телом возвращает исходный ответ создания: код 201 и первоначальный draft, даже после обновления заказа. Текущее состояние — через GET. Другое тело с тем же ключом → 409. Ключи общие на БД, без срока удаления; порядок позиций значим.
- Транзакции используют BEGIN IMMEDIATE: доступ SQLite сериализован, ожидание блокировки до 10 секунд. Это локальная демонстрация, не нагрузочный сервис; превышение ожидания блокировки может вернуть серверную ошибку.

Исходники: `studio/orderdesk/api.py`, `db.py`, `cli.py`, `demo.py`; миграция `migrations/versions/0001_initial.py` поставляется внутри пакета. Таблицы: customers, products, orders, order_items, audit_events, idempotency, alembic_version. Метки времени UTC. Аудит не защищён от прямого изменения файла БД. Перед обновлением сохраните БД при остановленном сервере; процедуры восстановления/downgrade не входят в поддерживаемый сценарий демо.

Нет авторизации, удаления, редактирования позиций, отдельного бизнес-интерфейса и конвертации валют. CLI слушает только 127.0.0.1; не размещайте публично без отдельной доработки доступа, HTTPS, лимитов и резервного копирования. Используйте синтетические адреса клиентов. Swagger UI по умолчанию загружает оформление с CDN, поэтому для интерактивной страницы может требоваться интернет.
