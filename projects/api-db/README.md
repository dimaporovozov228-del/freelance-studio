# Проект 2: Order Desk API — работающий локальный MVP

[Установка, демонстрация и ограничения](GUIDE.md) · [English](README.en.md).
Исходники: `studio/orderdesk/`; проверки: `tests/test_orderdesk.py`. Все примеры синтетические.

Сценарий: небольшая компания принимает заявки и ведёт позиции заказов; клиент видит проверяемые статусы и историю изменений.

Стек: Python, FastAPI, SQLAlchemy Core, Alembic, SQLite локально. PostgreSQL — последующий вариант. Один процесс, один файл БД; Docker и облако для демо не требуются. Зависимости устанавливаются через extra `api`, тестовые — через `test`.

Модель: customers(id, name, email); products(id, sku unique, name); orders(id, customer_id FK, status, created_at, version); order_items(id, order_id FK, product_id FK, quantity, price_minor); audit_events(id, order_id FK, action, timestamp). Денежные значения — целые минимальные единицы одной явно заданной валюты.

API: POST/GET /customers; POST/GET /products; POST /orders с Idempotency-Key; GET /orders/{id}; GET /orders с пагинацией; PATCH /orders/{id}/status с version; GET /orders/{id}/events; GET /health.

Правила: транзакция на заказ вместе с позициями; уникальный SKU; запрет отрицательных цен; ограничения FK; статусы draft → confirmed → completed либо cancelled; завершённые заказы неизменяемы. Конкурентное обновление возвращает 409. Повторный Idempotency-Key с иным телом возвращает 409, с тем же — исходный результат. Вход валидируется до записи.

Приёмка: миграция пустой БД; seed синтетических данных; OpenAPI; тесты happy path, 422/404/409, отката транзакции, FK, пагинации и повторного запроса. Демо: создать заказ → изменить статус → показать аудит → повторить запрос без дубля.

Публичное размещение потребует отдельного этапа: авторизация, разграничение клиентов, секреты, HTTPS, резервные копии и восстановление. В демо запуск только локальный. Показатель результата — воспроизводимые тесты и сценарий, без выдуманных метрик бизнеса.

Реализованы: создание/списки клиентов и товаров, создание/чтение заказов, статусы, аудит, миграция, seed и воспроизводимый HTTP-сценарий. Редактирование клиентов, товаров и позиций, удаление, авторизация и публичное размещение пока не реализованы.
