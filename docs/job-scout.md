# Job Scout: рабочий каркас и расширение

Сейчас реализован офлайн-импорт `examples/jobs.json`, дедупликация `(source,id)` и прозрачная оценка. Нет сетевых запросов, автоматического поиска на площадках и отправки откликов.

Обязательные поля: id, source, source_type=manual_export, permission_note, title, description; url необязателен. permission_note фиксирует основание использования данных, но не доказывает юридическое разрешение: это проверяет владелец перед импортом.

Формула: +20 за каждое упоминание python/excel/csv/api/automation/sqlite, -30 за каждый индикатор captcha/spam/scraping/unlimited/guaranteed profit; границы 0..100. Это эвристика по подстрокам на английском, не оценка вероятности получения заказа и не коммерческая экспертиза. Бюджет и сроки пока оценивает человек. Результат содержит совпадения, риски, вопросы и `decision=manual_review`.

Расширение источников:

1. Ручная разрешённая выгрузка или собственные данные — реализовано.
2. Письма с уведомлениями из собственного ящика — будущий адаптер, доступ только после согласования прав.
3. Официальный API — будущий адаптер, только после проверки доступности, документации и условий конкретной площадки, с минимальными правами, rate limit и курсором.
4. RSS — только если источник явно предоставляет и разрешает такое использование; адаптер пока отсутствует.

Автоматическое чтение HTML, обход авторизации/CAPTCHA и отправка откликов не предусмотрены. На данный момент никакие Upwork/API/RSS-источники не заявлены как доступные или разрешённые.

Будущий контракт адаптера: fetch(cursor) → normalized_jobs + next_cursor. Реестр хранит owner, разрешение, URL условий, дату проверки, rate limit, enabled=false по умолчанию. Для каждого подключения нужны контрактные тесты, обработка 401/403/429 и журнал без секретов. После получения → нормализация → дедупликация → оценка → очередь человека. Непроверенные источники остаются отключены.

Ручной разбор: границы задачи, образец данных, критерии приёмки, доступы, сроки, условия оплаты. После решения человека можно подготовить черновик предложения, используя только подтверждённые возможности портфолио; отправляет человек.
